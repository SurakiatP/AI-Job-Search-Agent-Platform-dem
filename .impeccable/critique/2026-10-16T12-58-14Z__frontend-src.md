## What works

- Grouped navigation and the explicit project switcher reflect the job-search lifecycle. The default Applications List supports scanning while Board remains available.
- Document history and session pairing keep the chosen source material visible. Keyword coverage is separate from AI assessment; application tracking does not imply real submission.
- Thai layouts and dark surfaces retain written status information and usable primary actions.

## Material findings and disposition

1. Job Detail omitted the evaluated CV/version and labelled document revisions as job revisions. Corrected using the existing immutable session pair, with honest lookup failure and retry; no invented RunView field.
2. Profile automatic-approval copy overstated submission behavior. Corrected to approval of recording Applied.
3. Thai application stage-menu labels were English. Localized both List and Board actions.
4. Project-token dialog allowed accidental outside dismissal. Outside interactions now preserve the dialog; deliberate Escape/dismissal still clears the one-time value, with a bilingual warning.
5. Deep-linked mobile settings could hide their active section. The selected item is now scrolled into view.
6. The shipped finish review found obsolete landing Keychain/provider-count/local-AI claims. Both languages, including hero and tour privacy copy, now describe configured gateway assistance and necessary external CV processing.
7. Document Detail had a redundant eyebrow above its title. Removed while preserving back navigation and metadata.
8. Historical direction-seed corroboration was initially absent from the packet. Restored the original recorded tool output and independently matched its call, timestamp, seed/index and SHA256; no reroll or fabricated evidence.

The detector ran once: one side-tab warning, zero errors, for an unused legacy CSS selector. The unused rule was removed without a second scan. A live injected overlay was unavailable because native browser evaluate is read-only. No overlay was claimed.
