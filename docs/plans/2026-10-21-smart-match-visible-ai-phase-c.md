# Smart match visible AI (Phase C) — implementation plan

Spec: docs/superpowers/specs/2026-10-21-smart-match-accuracy-design.md, Phase C (FR-SM-07..09, AC-SM-07, AC-SM-08). Branch feat/smart-match-visible-ai (from origin/develop 489f97c).

## Global Constraints
- Evidence must be extracted deterministically from the CV text (no new model call, no extra cost): AC-SM-07 requires every evidence string to be a substring of the CV text. Jev returns typed answers only, so quotes cannot come from it.
- Backend stays additive: `ai_match` gains an `evidence` object; nothing is renamed or removed; API stays under `/v1`; update docs/contracts/application-api.yaml (the `ai_match` schema) in the same change.
- Frontend: React/TS/Tailwind/Radix, existing i18n files (common.th/en.json or the feature copy objects used in SearchPage), Thai and English both; follow DESIGN.md/PRODUCT.md and the journey-stage hues already in styles.css (search stage = `--stage-search`); corner and button rules as already in components/ui. No black. Mark AI output with the existing `AiMark`/`AiLabel` components.
- Tests first and seen failing; mutation-check the key rule (substring guarantee). Run backend unit tests and `npm test --prefix tests -- --reporter=dot` (Playwright, mocks must mirror any new field) plus `cd frontend && npx tsc --noEmit -p . && npm run build`.
- No change to scoring, prompts, model, or cost.

## Task 1: evidence lines (backend, FR-SM-07)
Add to `backend/src/job_search_platform/services/smart_match.py` a pure `evidence_lines(cv_text: str, skills: list[str], limit: int = 160) -> dict[str, str]`: for each skill that `skill_mentions(cv_text)` finds, the whole line (text between newlines, stripped) containing its first mention, truncated at a word boundary to `limit` chars with no added characters other than a trailing "…" when truncated (the part before "…" must still be a substring). Skills not found in the CV are omitted. In `api/rest.py` (the Smart match list endpoint around the `ai_match` assembly) load the CV revision text (`CVRevisionText`, as the worker does) once and set `item["ai_match"]["evidence"] = evidence_lines(cv_text, ai_match["skills_evidenced"])` only when a score row exists; when the CV text is unavailable return `{}`. Tests (backend/tests/unit/test_smart_match_evidence.py + an integration assertion in backend/tests/integration/test_smart_match_api.py): every returned line (minus a trailing "…") is a substring of the CV text for the Thai and English synthetic CVs in backend/tests/smart_match_eval/data/cvs.json; skill absent -> omitted; truncation rule; response contains `evidence` for scored rows and no key problems for unscored rows. Mutation: return a paraphrase (e.g. lower-case/strip a word) and see the substring test fail.

## Task 2: evidence and next step in the job detail (frontend, FR-SM-07, FR-SM-09, AC-SM-08)
In `frontend/src/features/search/SearchPage.tsx` (`MatchSummary`) add the field to `AiMatch` in the API types, and show under "Evidenced in your CV" each skill with its quoted CV line (quote styling, line clamps to two lines with the full text in a title/tooltip, escaped as plain text). For each missing must-have chip add a small link "Tailor CV for this job" that goes to the existing CV-tailoring entry for this job (find the real route/dialog used by the evaluation flow; if tailoring needs an evaluation session first, link to the new-evaluation dialog for that job instead and say so in the report). Add Thai and English copy. Update Playwright mocks/fixtures for the new field and add one e2e test (evidence visible in th and en, 390 and 1440, no horizontal overflow). Screenshots of both widths and both languages for the report; light and dark.

## Task 3: agent steps while ranking (frontend, FR-SM-08)
While a Smart match run is active, replace the generic spinner text with the agent's steps (reading your CV, shortlisting jobs, scoring i of N) derived from data the page already has (run status + `ai.scored` / pool size from the list response, and run events if the page already consumes them; do not add polling or endpoints beyond what exists; state in the report what source was used). Steps are announced politely to assistive tech (`aria-live="polite"`), respect reduced motion, and use the search stage hue. Add i18n copy and one Playwright test (mock a run moving through states).
