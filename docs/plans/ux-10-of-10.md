# Plan: User Journey, User Flow, Wireframe and UI Design to 10/10

Status: proposal for owner review, 2026-11-04. Builds on `docs/design/ux-foundation.md`.
Baseline (self-assessed, same session): Journey 4 → 5.5, Flow 5 → 6.5, Wireframe 3, UI Design 7.
Targets below marked **[Proposed]** are the team's proposal until the owner accepts them (no client decision yet).
Effort and dates belong to the PM; this plan gives order and dependencies only.

## 1. What 10/10 means (acceptance rubric)

A stage scores 10 only when every item in its row is true and has evidence in `docs/`.

| Stage | 10/10 means | Evidence that proves it |
|---|---|---|
| User Journey | Personas and journeys come from real users of this customer (≥5 interviews or observed sessions per primary persona), each pain point cites participant codes, first-time and returning journeys exist, the customer has reviewed them | `docs/research/UXR-*.md`, updated `ux-foundation.md` with quotes, customer sign-off in RAID |
| User Flow | Every core task (6, §3) has a flow diagram with happy, error, empty, cancel and no-permission branches, traced to FRs and screens (SCR); IA/navigation map and user-term glossary exist; flows were designed before the screens they drive | `docs/design/flows/*.md` (Mermaid), `docs/design/ia.md`, `docs/glossary.md` |
| Wireframe | Low-fidelity wireframes for every screen in the inventory whose structure is new or changed, made before build, 2–3 options for each major screen, a click-through prototype tested with ≥5 users before code | `docs/design/wireframes/` (grey-box HTML), test notes, chosen option recorded as DEC |
| UI Design | Visual direction frozen in `DESIGN.md` (changes only through a CR), every SCR built with all states (empty, loading, error, success, no permission, long Thai text), design QA passed against the wireframes, WCAG 2.2 AA audit with no open sev 3–4, usability test on the built app meets the targets below | `docs/design/screens.md`, design QA report, a11y report, usability report |

Usability targets for the built app **[Proposed]**, measured in the round-3 test (§2 phase 6), 5–8 participants:
- Task success without help ≥ 90 % on each core task.
- First CV to first fit score in ≤ 5 minutes median (excluding AI wait), measured from screen recording.
- No severity 3–4 issue left open.
- SUS score ≥ 80 (industry "good–excellent" band; method: standard 10-item SUS, Thai translation).

## 2. Phases

Each phase lists what I (the team) can do alone and what needs the owner or customer. A phase starts only when the one before it is done, except Phase 1, which runs alongside.

### Phase 0 — Decisions (owner)
- Answer Q-01 to Q-05 in `ux-foundation.md` §5.
- Freeze the visual direction: current Gemini blue, Google Sans Flex + Anuphan. After this, look changes go through a CR. This fixes the "direction changed 3 times in 2 days" gap.
- Agree the rubric (§1) and the usability targets.

### Phase 1 — Quick wins (team, in parallel, no research needed)
Pain points that are already evidenced (sev 3–4 or clear owner feedback):
- PP-03 release the OCR/16k fix to prod (needs owner go-ahead for deploy).
- PP-09 / PP-05 one-line explanation "คะแนนคิดจาก CV ฉบับนี้" at the CV choice and on the score; rename the experience bank in user terms.
- PP-01 verify-email banner with resend on Today before the first AI action.
- PP-06 "สกัด CV" → "ดึงประสบการณ์จาก CV".
These become the baseline that Phase 2 measures.

### Phase 2 — Research (needs customer: recruit users)
- Recruit 5 users per primary persona (P1 new graduate, P2 experienced switcher) through the customer. PDPA consent form; no real CVs kept after the session (users may use their own CV on screen only).
- Team prepares: screener, interview guide (30 min: how they job-hunt today, tools, fears), 5 non-leading tasks on the current app, note template, consent text.
- Measure the baseline: task success, time, errors, SUS.
- Output: `docs/research/UXR-xx` findings (observations kept apart from interpretation), participant codes only.

### Phase 3 — Journey and IA (team, from Phase 2 data)
- Rewrite personas from data; drop or merge hypotheses that the data does not support.
- Journey maps (first-time, returning) with real quotes and measured friction; opportunity list ranked by severity × frequency.
- IA map: navigation, page names in the users' own words (glossary), what lives on which page (fixes the CV vs experience-bank confusion at the model level, not only with copy).
- Customer review of personas and journeys → sign-off recorded in RAID.

### Phase 4 — Flows and screen inventory (team)
- Six core task flows as Mermaid diagrams, each with error, empty, cancel and no-permission branches, traced to FR and SCR:
  1. Sign up and verify, 2. Add CV (and extract), 3. Find job and evaluate, 4. Tailor CV, 5. Draft documents, 6. Record and track an application (incl. practice).
- `docs/design/screens.md`: one row per screen (SCR-xx), roles, FRs, states covered.
- Surface closure check both ways (every need has a screen; every screen is reached by a flow).

### Phase 5 — Wireframes and prototype test (team builds, needs 5 users to test)
- Grey-box HTML wireframes for screens that are new or change structure after Phase 3–4 (expected: first-run/Today, CV + experience, evaluation result, document reading inside the job).
- 2–3 labelled options for each major screen with tradeoffs and a recommendation; owner picks → DEC.
- Click-through prototype of the chosen options; test with 5 users (round 2) on the same tasks. Fix sev 3–4 before any code.

### Phase 6 — Build, QA and validation (team, then 5–8 users)
- Build the chosen wireframes in the frozen design system; every SCR state present.
- Design QA: built screen vs wireframe, screenshots 1440 / 390, Thai long text.
- Accessibility audit WCAG 2.2 AA (keyboard, focus, contrast, target size, reduced motion, screen reader on core flows).
- Usability round 3 on the built app; compare with the Phase 2 baseline and the §1 targets.
- Hand the results to UAT.

## 3. Dependencies and risks

| Item | Depends on | Risk if skipped |
|---|---|---|
| Journey 10/10 | Phase 2 real users | Cannot pass: without users the personas stay hypotheses (max ~6/10) |
| Wireframe 10/10 | Phase 3–4 done first | Wireframes would just redraw the current app |
| UI Design 10/10 | Direction frozen (Phase 0), round-3 test | Another restyle restarts QA |
| Usability targets | Recruiting through the customer | Targets unmeasurable |

Honest limit: the team can reach about Journey 6, Flow 9, Wireframe 7, UI 8 without real users. The last points in every row need Phase 2, Phase 5 and Phase 6 tests with people from the customer's audience.
