# LiteLLM Gateway Implementation Plan

> Execution: superpowers:subagent-driven-development. Implementers run on Sonnet with disjoint file ownership, so T1, T2 and T3 can run in parallel. Each task gets a task review; the whole branch gets one Opus review at the end.
> The owner approved the design in chat on 2026-10-10 (grill Q1–Q12): "ตรงแล้ว ลุยเลย".

**Goal:** All LLM traffic goes through a project-owned LiteLLM gateway. Hermes chat calls use the `ai-analyze` model. Jev `decisions` calls go through a LiteLLM pass-through route. The in-app provider settings (form, endpoints, Keychain at runtime) go away. A read-only gateway status replaces them.

**Branch:** `feat/litellm-gateway` from `origin/develop` (bc1c43d).

## Decisions (binding)
- LiteLLM is our own service in `infra/compose.yaml`. It runs on `127.0.0.1:4000`, has its own Postgres (`litellm-db`, reusing the project's patched `job-search-platform/postgres` image with a separate volume), and runs with `STORE_MODEL_IN_DB=True` so the owner manages models in the LiteLLM UI at `/ui`. Never use the unrelated `litellm` container from another project.
- Model aliases:
  - `ai-analyze` → `openrouter/z-ai/glm-5.3-flash`. A first-start seed adds it if absent. The owner can later change it in the UI.
  - `ai-decision` → Jev `typesafe/jev-1.13` through the OpenRouter **decisions** API (`https://openrouter.ai/api/alpha/decisions`). It is not a chat model, so it cannot be a UI model. LiteLLM exposes it as an authenticated pass-through route `POST /jev/decisions`, and the model id comes from env `AI_DECISION_MODEL`.
- Secrets:
  - `OPENROUTER_API_KEY` reaches only the LiteLLM container, from the environment at `local_infra.py start` (the owner's `.env`).
  - LiteLLM master key, salt key, DB password and UI password are generated by `scripts/local_infra.py` into `CORE02_PRIVATE_DIR` (mode 0600), the same way as the existing Postgres/MinIO credentials.
  - The seed creates a LiteLLM **virtual key** for the app (alias `job-search-app`, models `ai-analyze`, pass-through allowed) and writes it to `CORE02_PRIVATE_DIR/litellm_app_key` (0600).
- App configuration (env, with defaults):
  - `LITELLM_BASE_URL=http://127.0.0.1:4000`
  - `LITELLM_API_KEY` (falls back to the `litellm_app_key` file)
  - `AI_ANALYZE_MODEL=ai-analyze`
  - `AI_DECISION_MODEL=typesafe/jev-1.13`
- Hermes gets `ProviderConfig(provider="custom", model=AI_ANALYZE_MODEL, base_url=LITELLM_BASE_URL + "/v1", api_key=<app key>)`. Hermes already supports custom OpenAI-compatible endpoints.
- Message logging/privacy (for phase B Langfuse) is out of scope here.
- Provider settings removal:
  - Delete `/providers`, `/settings/provider`, `/settings/provider/models` and `/settings/provider/test`, plus their service code paths, from the runtime.
  - Keep the `provider_configurations` table and old rows as history.
  - Do not touch the macOS Keychain contents.
  - New runs no longer need a provider configuration. `provider_configuration_id` stays NULL. A migration relaxes the run check constraint, and `config_snapshot` records `{"gateway": {"analyze_model": ..., "decision_model": ...}}`.
  - Admission fails with `gateway_unconfigured` (409) when no app key is available.
- New owner-only `GET /api/v1/gateway` → `GatewayStatusView {configured: bool, reachable: bool, base_url: str | null, analyze_model: str, decision_model: str, models: list[str]}`. It calls LiteLLM `GET /v1/models` with the app key and a 3 s timeout, and never returns a key.

## Global constraints
- Run backend tests from the repo root with `uv run --project backend pytest backend/tests/<path> -q`. The baseline failures are `test_application_startup` and `test_storage_infrastructure`.
- Secrets never go into git, logs, events, errors, test fixtures or agent output. Tests use fake keys. Do not read or print the owner's `.env`, Keychain items or private-dir secrets.
- Do NOT edit the owner's untracked files: `.env`, `.env.example`, `.gitignore`, `.python-version`. New configuration keys are documented in `docs/engineering/local-operation.md`.
- Pin images by digest. A new image must pass Trivy with 0 High/Critical, or the task stops and reports.
- `docs/contracts/application-api.yaml` must match the runtime OpenAPI (contract test).
- No `git stash`. Commit only your own files. Each commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Do not start, stop or restart the owner app on :8000/:8001 or the running storage containers. The controller does integration runs.

## Tasks

### Task 1: LiteLLM infrastructure
**Owns:**
- `infra/compose.yaml` (new `litellm`, `litellm-db` and `litellm-seed` services, plus their volumes and secrets)
- `infra/litellm/` (new: `config.yaml`, `seed.py`)
- `scripts/local_infra.py` (credential generation and passing `OPENROUTER_API_KEY` through)
- `docs/engineering/local-operation.md` (gateway section)
- `docs/engineering/dependencies.md` (LiteLLM image pin and scan)
- tests for local_infra, if they exist (search `backend/tests` for `local_infra`)

**Build:**
- Pin `ghcr.io/berriai/litellm-database` to a current stable tag plus its digest. Trivy-scan it first. If it has any High/Critical, STOP and report the IDs.
- `config.yaml`:
  - `general_settings.master_key: os.environ/LITELLM_MASTER_KEY`
  - `database_url` from env
  - `store_model_in_db: true`
  - `pass_through_endpoints`: path `/jev/decisions`, target `https://openrouter.ai/api/alpha/decisions`, header `Authorization: "Bearer os.environ/OPENROUTER_API_KEY"`, `auth: true`
  - No models in the file.
- `seed.py` (stdlib only, idempotent): wait for health. Create model `ai-analyze` (`openrouter/z-ai/glm-5.3-flash`, `api_key: os.environ/OPENROUTER_API_KEY`) if no model with that name exists. Create the `job-search-app` virtual key if absent. Write the key to the output path from argv/env with 0600. Never print keys.
- `local_infra.py start`:
  - Generate the four secrets into the private dir if absent.
  - Pass `OPENROUTER_API_KEY` from the caller's env to compose. If it is missing, start LiteLLM anyway, but the seed skips model creation and logs `openrouter_key_missing` without failing.
  - Mount the private dir (or only the key output file) for the seed.
  - `status` reports litellm health.
- Ports bind to 127.0.0.1 only.

**Acceptance:**
- `local_infra.py` unit tests pass, or new ones exist for secret generation and the env passthrough.
- `docker compose config` validates.
- The scan result is recorded.
- Do not run `start` against the owner's live stack. The controller does that.

### Task 4: Service addresses, readiness and logs (owner request 2026-10-10)
**Depends on:** T1 and T2 merged on the branch. It touches `scripts/local_infra.py`, `backend/src/job_search_platform/main.py` and `api/rest.py` after them.
**Owns:**
- `backend/src/job_search_platform/main.py`, `config.py` (new, if it helps)
- `api/rest.py` (health only)
- `integrations/logging.py` (new)
- `scripts/local_infra.py`, `scripts/run_local.py`
- `.env.example` and the owner's `.env`. The owner explicitly asked for these to be edited. For `.env`: append missing keys only, never print or rewrite existing values.
- `docs/engineering/local-operation.md`
- tests for these

**Build:**
- **Addresses come from env, with today's defaults.** Every service address the app uses is read from env:
  - `JSP_POSTGRES_HOST` (127.0.0.1), `JSP_POSTGRES_PORT` (55432, replacing `CORE02_POSTGRES_PORT` but still honouring it), `JSP_DATABASE`
  - `JSP_MINIO_ENDPOINT` (`http://127.0.0.1:59000`), `JSP_PRIVATE_BUCKET`
  - `LITELLM_BASE_URL`
  - `LANGFUSE_HOST` (reserved; used in branch 2)
  - `OTEL_EXPORTER_OTLP_ENDPOINT` (existing)
- **No secrets in `.env.example`.**
  - Secret keys appear in `.env.example` with empty values and a comment: `OPENROUTER_API_KEY`, and `LITELLM_API_KEY` (optional; falls back to the private-dir file).
  - Generated infrastructure secrets never appear in either file. These are the DB/MinIO passwords, the LiteLLM master and salt keys, and the LiteLLM DB password.
  - `.env.example` gets a header section that explains which values belong where.
- **Readiness.** `GET /api/v1/health` stays liveness. New `GET /api/v1/health/ready` returns `{"status": "ok"|"degraded", "components": {"postgres": "ok"|"down", "object_store": ..., "llm_gateway": ..., "sandbox_image": ...}}`.
  - Each check is bounded: about 2 s timeout per check, run concurrently.
  - It is unauthenticated, but returns no addresses, versions or error text.
  - It returns HTTP 200 when ok and 503 when degraded.
  - Add both paths to the contract YAML.
- **Logs.** Configure stdlib logging to emit one JSON line per record on stdout: `ts`, `level`, `logger`, `msg`, `request_id`.
  - Add request middleware that assigns or propagates an `X-Request-ID` header (validated as a uuid or 1–64 safe characters). It logs method, route template (not the raw path with ids), status and `duration_ms`.
  - Never log headers, bodies, query strings, tokens or CV text.
  - Level comes from `JSP_LOG_LEVEL` (default INFO).
  - Keep the existing redaction filters.
- **Docs.** `local-operation.md` gains a "Configuration and multi-host" section listing every env key, its default and whether it is secret.

**Acceptance:**
- Unit tests for env parsing and defaults.
- Readiness test: all ok gives 200; LiteLLM down gives 503 with `llm_gateway: down` and no leaked address.
- Log test: a request produces one JSON line with `request_id` and the route template, and contains no token or query values.
- Full backend suite and the contract test pass.
- **One private-dir default.** `scripts/local_infra.py` reads `CORE02_PRIVATE_DIR` from the environment and falls back to the same default as `main.py`: `~/.cache/job-search-platform/core02-runtime-20261003`. Today it defaults to `~/.local/share/job-search-platform/core02`, so the private dir must be set in `.env`. After this change `CORE02_PRIVATE_DIR`, `MINIO_SOURCE_DIR` and `GOSU_SOURCE_DIR` are all optional overrides. In `.env.example` they are commented, with a note explaining that. Existing values in the owner's `.env` stay as they are, because they equal the defaults.
