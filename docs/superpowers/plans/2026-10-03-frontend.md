# Bilingual Frontend Implementation Plan

> **For agentic workers:** Execute with `delegate-build` and the waves in [the master plan](2026-10-03-platform-implementation.md). Use checkbox steps and preserve exclusive file ownership.

**Goal:** Convert the approved mockup into an accessible Thai/English application connected to the actual local workflow.

**Architecture:** Feature folders use the same typed API client and error mapping. React Router preserves navigable URLs; in-memory drafts are keyed by Project/Session. Global language/theme providers drive every page without changing document language or entered text.

**Tech Stack:** React/TypeScript/Vite, Tailwind/shadcn, React Router, react-i18next, browser fetch/SSE and Playwright.

## Global Constraints

Read DESIGN.md in full before implementation. Use the existing approved mockup as the visual reference, not as executable application source. App name is **AI Job Search Agent Platform**. Select open chat with optional document panel, warm-white/teal, no animation. Do not include a login/account page or a fake backend response in product paths.

LocalStorage may hold UI locale/theme only; never API keys, project credentials, raw CV/chat or uploaded document contents. Keep pending text in memory while changing page/language/theme. Backend documents determine completed data after reload; browser persistence is not a substitute for server state. Draft document language is explicitly selected, independent of UI locale.

## Review Focus

- Switching locale/theme must not lose user input, selected Project/Session or current Settings tab.
- Browser back/forward, direct URLs and 320px width must work on every page.
- Active runs survive a closed browser, and reconnect deduplicates persisted SSE sequences.
- Secret/token controls never reveal stored values or persist them in browser storage.
- Failed/scanned uploads, interrupted execution, approval expiry and partial documents have clear distinct states.

## Routes and API ownership

Use these routes; UI-02 creates the router in one task, and the root integrator performs subsequent shared wiring:

```text
/                                             landing
/app                                          latest Session or Projects redirect
/app/projects                                 Projects
/app/projects/new                             new Project
/app/projects/:projectId/profile               CV/preferences
/app/projects/:projectId/sessions/:sessionId    chat
/app/projects/:projectId/jobs                  saved jobs
/app/projects/:projectId/jobs/:jobId            job detail
/app/projects/:projectId/documents             documents
/app/projects/:projectId/documents/:documentId document detail
/app/settings                                 appearance, providers/tools, project sharing
```

Unknown resource IDs show a localized not-found state and a working route back to Projects. Deep links remain scoped by the backend; sidebar selection is derived from the URL.

Shared backend DTOs come from CORE-04's API schema. UI-03 owns `frontend/src/lib/api.ts` and `frontend/src/lib/run-events.ts`; UI-04 reads those interfaces and proposes any changes to root. A helper has the fixed shape:

```ts
type ApiError = { code: string; message_key: string; retryable: boolean; correlation_id?: string };
type RunEvent = { sequence: number; run_id: string; kind: string; payload: PublicEventPayload };
async function apiRequest<T>(path: string, init?: RequestInit): Promise<T>;
function watchRun(projectId: string, runId: string, after: number, onEvent: (event: RunEvent) => void): () => void;
```

Use same-origin credentials and owner CSRF headers. PublicEventPayload is the generated/synchronized discriminated API type, not `any`. A stream deduplicates by run ID plus sequence and requests replay after the last observed sequence. API errors localize by message_key; no raw stack/error body is displayed.

- [ ] Build Header, ProjectSidebar, MobileDrawer, Button, Tabs, Dialog, EmptyState and StatusNotice components only where actual pages need them. Header contains the language switch at top-right on every route and width. No CSS transitions/animations or motion library.

```ts
test('locale and theme preserve an entered draft', async ({ page }) => {

  await page.getByRole('button', { name: 'Dark' }).click();
  await expect(page.getByRole('textbox', { name: 'Message' })).toHaveValue('สนใจงานนี้');

```

- [ ] Run `rtk proxy npm run build --prefix frontend` and `rtk proxy npm test --prefix tests -- shell.spec.ts`. Product main initially renders the genuine shell; root wires the router after UI-02. Red fails on missing/prematurely reset input; green proves language/theme behavior without depending on later chat implementation. Inspect shell at 320px and desktop.

**Acceptance:** Shared typography/colors/header/themes work with keyboard and mobile, without losing input or animations.

- [ ] Bind Project/Session CRUD, CV upload/preferences, supplied job revisions and document views through root-integrated feature hooks. - [ ] Composer creates an idempotency key per intent, disables duplicate clicks for pending submission and retains that key on retrying a network-uncertain submission. Closing a page unsubscribes without cancelling execution.
- [ ] Render queued/running/waiting_approval/completed/failed/cancelled/interrupted. Show actual revision references, partial output labels, retry as a new run and cancel requested until stop is confirmed. Owner approval presents exact target/revision/change and expiry; stale/expired errors refresh the state rather than silently apply changes.

