# Job search on Meilisearch (TOR FR-J01, WP5 part 2) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every job search feature reads one Meilisearch index fed from the part-1 job store. `search_jobs` and `job_facets` keep their shapes, add an optional `company` filter, and stop calling freehire at query time.

**Architecture:**
- A pinned `meilisearch` compose service with a master key held in the private dir.
- A stdlib REST client in `integrations/meili.py`.
- `services/job_index.py` builds documents from `job_postings`, syncs dirty rows and queued deletes after each ingest, and rebuilds through an index swap.
- `services/job_sources.py` turns the existing query parameters into a Meilisearch search through one seam, `_search(payload)`. Tests replace that seam.

**Tech Stack:** Python 3.12 stdlib (`urllib`, `json`), Meilisearch CE v1.55.0 (MIT), SQLAlchemy 2.1, pytest.

**Spec:** `docs/superpowers/specs/2026-10-14-job-search-index-design.md` (amended 2026-10-15)

## Global Constraints

- Branch `feat/job-search-index` from fetched `origin/develop`. Prefix shell commands with `rtk`.
- No new Python dependency. The Meilisearch client is stdlib (spec E5). `requirements.txt` stays unchanged, and its drift test must still pass.
- Image `getmeili/meilisearch:v1.55.0` is pinned by multi-arch index digest in `infra/compose.yaml`. It listens on `127.0.0.1:57700:7700` only, with `MEILI_ENV=production` and `MEILI_NO_ANALYTICS=true`.
- The master key lives in the private dir file `meili-master-key`, generated by `scripts/local_infra.py` (0600). It never appears in the repo, logs, CLI output or test fixtures.
- Env: `MEILI_URL` (default `http://127.0.0.1:57700`), `MEILI_INDEX` (default `jobs`; tests use throwaway names).
- Index `jobs`, primary key `id`. Documents hold canonical postings only (`canonical_id IS NULL`).
- Meilisearch down means `ServiceError("job_source_unavailable", retryable=True)`. There is no fallback to Postgres (E4, FR-J01).
- `stale` is `reality_stale OR age_days > 60` (`STALE_AFTER_DAYS = 60`).
- Sync after ingest:
  - deletes first, then dirty upserts;
  - batches of 1,000 and a 120 s wait per task;
  - a 5-minute sync budget;
  - an index failure never rolls back the store and is recorded as `index_failed`.
- Test data is synthetic. Unit tests make no network calls. Tests against real Meilisearch are marked `integration` and skip when it is unreachable.

## Review Focus

1. **Filter injection.** A city or skill value containing `"` or `\` must be escaped, and must never widen the filter. Task 2 `test_filter_values_are_escaped`.
2. **A merged (non-canonical) posting stays searchable** after its cluster changes. Sync must delete it from the index. Task 3 `test_merged_posting_is_removed_from_index`.
3. **A Meilisearch outage during ingest** must leave the store committed and the rows dirty for the next run. Task 4 `test_index_failure_keeps_store_and_dirty_rows`.
4. **Empty `q` browsing** must sort newest first. A query must rank by relevance and not be forced into date order. Task 5 `test_empty_query_sorts_newest_first`.
5. **The landing stats** (`/public/job-stats`, no auth) must not hit Meilisearch on every request. Task 5 keeps the 300 s cache: `test_facets_are_cached`.

**Interfaces:**
- Produces, in `integrations/meili.py`:
  - `class MeiliError(Exception)`
  - `class Meili(url: str, key: str, *, transport=None)` with these methods:
    - `request(method, path, body=None) -> dict | list`
    - `wait(task_uid: int, deadline_s: float = 120) -> None` raises `MeiliError` on failed, canceled or timeout
    - `index_exists(index) -> bool`
    - `update_settings(index, settings) -> int` (task uid)
    - `add_documents(index, docs) -> int`
    - `delete_documents(index, ids) -> int`
    - `search(index, payload) -> dict`
    - `create_index(index) -> int`
    - `swap(a, b) -> int`
    - `delete_index(index) -> int`
  - `transport(method, url, headers, body_bytes, timeout) -> (status, bytes)` is injectable. The default uses `urllib` with no redirects, `ProxyHandler({})`, an 8 s timeout and an 8 MiB response cap.
  - `quote(value: str) -> str` returns a Meilisearch filter string literal: wrapped in `"`, with `\` and `"` escaped.
  - `client() -> Meili` builds from `config.meili_url()` and the private key file. It reuses `job_search_platform.main._private_text("meili-master-key")` lazily, never at import.

- [ ] **Step 3: Implement `job_index.py`.**
  - `sync` order:
    1. If `not client.index_exists(index)`, call `rebuild` and return `rebuilt`.
    2. Read queued delete ids, send `delete_documents` in batches and `wait`, then delete those queue rows.
    3. Select dirty rows with `defer(description_markdown)` off (the description is needed).
    4. Upsert the canonical ones (sources = the distinct `source` values of the canonical and its members) and `wait`.
    5. Delete the non-canonical ones and `wait`.
    6. Clear `index_dirty` for the ids of each batch that succeeded.
  - Check the budget before each batch. If it is exceeded, stop and return `index_failed`; the remaining rows stay dirty.
  - Wrap everything in `try/except MeiliError`, which returns `index_failed`.
  - `rebuild`:
    - creates `f"{index}_tmp"`, deleting it first if it exists;
    - applies `SETTINGS`;
    - writes all canonical rows in id order in batches;
    - swaps, then deletes the tmp index;
    - finally, in one transaction, sets `index_dirty=false` for all rows and deletes queue rows created before the rebuild started.
